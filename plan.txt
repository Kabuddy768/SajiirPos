1. Role Architecture
Your current codebase already defines five roles in TenantUser. Here is a complete breakdown of what each role should be allowed to do, including the multi-branch scenario you raised.
1.1 The Five Roles Explained
Role
Who They Are
What They Can Do
Owner
The person who purchased the subscription
Everything. Manage tiers, billing, all branches, all staff. Cannot be removed.
Admin
A trusted operator — like an IT or ops head
Full access to all branches. Manage products, staff, reports. Cannot change billing.
Manager
Branch manager
Manage their assigned branch only. Approve returns, view reports, add products for that branch.
Cashier
Till operator
Open session, make sales, process returns below KES 5,000 threshold. Cannot see reports.
Auditor
Accountant or compliance officer
Read-only access to all reports and audit logs. Cannot make any changes.
1.2 Do You Need a 6th Role?
Based on your codebase and business model, here is a recommendation:
RECOMMEND
Add a Supplier contact role in future. For MVP, your five roles are sufficient. Do not add roles until you have a clear use case.
1.3 Multi-Branch Role Problem — Your Question Answered
You asked: "In Branch A I am a cashier, but in Branch B I am a manager. Same email. How does that work?"
The answer is to separate two things that your current code conflates:
Concept
Model
Scope
Purpose
Tenant Role
TenantUser.role
Whole tenant / all branches
Highest-level permission cap
Branch Role
StaffProfile (new field)
One specific branch
Fine-grained branch permissions
Implementation: Add branch_role to StaffProfile
Add one field to your existing StaffProfile model:
# apps/branches/models.py
class StaffProfile(models.Model):
    user    = ForeignKey(User, ...)
    branch  = ForeignKey(Branch, ...)
    is_active = BooleanField(default=True)
    # ADD THIS:
    branch_role = CharField(max_length=20, choices=ROLE_CHOICES, default='cashier')
Now one user can have:
StaffProfile(branch=A, branch_role="cashier")
StaffProfile(branch=B, branch_role="manager")
Update your get_user_role() permission helper to check StaffProfile.branch_role first, falling back to TenantUser.role if no profile exists for the current branch. The TenantUser.role acts as a ceiling — a cashier-level TenantUser can never exceed cashier even if a StaffProfile grants more.
RULE
TenantUser.role = ceiling. StaffProfile.branch_role = actual role for that branch. Never let branch_role exceed the ceiling.

2.2 How to Enforce Tiers in Code
Create a single file: apps/tenants/tier_limits.py
# apps/tenants/tier_limits.py
TIER_LIMITS = {
  'starter':    {'branches': 1,  'staff': 5,  'etims': False, 'transfers': False},
  'pro':        {'branches': 3,  'staff': 15, 'etims': True,  'transfers': True},
  'enterprise': {'branches': 999,'staff': 999,'etims': True,  'transfers': True},
}
def can_add_branch(tenant):
    from apps.branches.models import Branch
    limit = TIER_LIMITS.get(tenant.plan, {}).get("branches", 1)
    return Branch.objects.filter(is_active=True).count() < limit
def can_add_staff(tenant):
    limit = TIER_LIMITS.get(tenant.plan, {}).get("staff", 5)
    return TenantUser.objects.filter(is_active=True).count() < limit
Call these functions in your views before creating a branch or inviting a staff member. Return a 403 with an upgrade prompt if the limit is reached.

3.2 New Model: StaffInvitation
Create this in apps/branches/models.py or a new apps/invitations/ app:
# apps/invitations/models.py
import uuid
class StaffInvitation(models.Model):
    email        = EmailField()
    role         = CharField(max_length=20, choices=TenantUser.ROLE_CHOICES)
    branch       = ForeignKey(Branch, null=True, blank=True)
    token        = UUIDField(default=uuid.uuid4, unique=True, editable=False)
    invited_by   = ForeignKey(settings.AUTH_USER_MODEL, on_delete=PROTECT)
    expires_at   = DateTimeField()  # now() + 48 hours
    accepted_at  = DateTimeField(null=True, blank=True)
    is_used      = BooleanField(default=False)
    created_at   = DateTimeField(auto_now_add=True)
    def is_valid(self):
        return not self.is_used and timezone.now() < self.expires_at

4.3 How to Redirect After Login
Add a post_login redirect function in your frontend_urls.py or a middleware:
# apps/tenants/redirects.py
def get_post_login_url(request):
    role = get_user_role(request)
    if role in ['owner', 'admin', 'manager']:
        return '/dashboard/'
    elif role == 'cashier':
        return '/'  # POS till screen
    elif role == 'auditor':
        return '/dashboard/reports/'
    return '/'
Set LOGIN_REDIRECT_URL in settings to point to a view that calls this function rather than hardcoding a URL.
